# Building a Distortion Plugin: Managing Aliasing in DSP

Conventional non-linear distortion introduces aliasing in the digital domain — sampling a signal at a rate low enough that the harmonics it generates fold back into the audible range as inharmonic artifacts. Since a plugin cannot force the host DAW to run at a higher sample rate, this project implements a multi-rate architecture that isolates the non-linear stage inside a high-resolution oversampled environment, keeping the resulting distortion harmonic while attenuating digital artifacts.

The filter design rationale draws on a Stanford EE264 paper by Woody Herman, *DSPFuzz: A Guitar Distortion Pedal Using The Stanford DSP Shield*, which outlines the multi-rate architecture and filter design considerations for this class of problem.

---

## Three Stages, One Signal

Replicating analog-style distortion digitally requires oversampling — a simple waveshaping function applied at the native rate is not sufficient to prevent foldback.

### Stage 1 — Pre-Processing (Native Rate)

The signal arrives at the host's sample rate, typically 44.1 kHz. A variable input drive scales the signal, and a 1st-order high-pass filter attenuates sub-bass content before it reaches the waveshaper, preventing low-frequency intermodulation. These are linear operations, so there's no aliasing risk and no need to spend CPU cycles upsampling them.

### Stage 2 — The Nonlinear Core (8× Oversampled)

High-order linear-phase equiripple FIR filters (provided by the JUCE framework) increase the sample rate to 352.8 kHz. At this resolution, the harmonics generated by the waveshaper occur well above the audible range, allowing them to be filtered out before decimation.

For the waveshaper itself, I diverged from the original paper. Herman's implementation uses rational and polynomial approximations suited for fixed-point DSP hardware. Without those hardware constraints, I used an asymmetric tanh(x) soft clipper, which treats the positive and negative halves of the waveform slightly differently to generate even-order harmonics and give the distortion an analog character.

A DC blocker sits immediately after the waveshaper to correct the offset introduced by asymmetric clipping. A steep FIR decimation filter then attenuates frequencies above the original Nyquist limit before the signal is downsampled back to the native rate.

### Stage 3 — Post-Processing

Back at the native rate, a low-pass post-EQ filter attenuates residual high-frequency artifacts, and an output trim normalizes the final level. A phase-accurate dry/wet mixer blends the processed and unprocessed signals, and the full plugin state is serialized to JSON for DAW session recall.

## Challenges

**The Tone Knob Abstraction**
The user sees a single tone control. Under the hood, that one 0.0–1.0 float simultaneously drives the pre-distortion high-pass cutoff upward and the post-distortion low-pass cutoff downward. Decoupling the user-facing control from the underlying dual-filter behavior was a practical exercise in parameter mapping.

**Parameter Smoothing**
Every user-facing parameter runs through a ~20ms linear smoothing ramp. Without it, an instantaneous parameter jump creates a mathematical discontinuity in the signal — audible as a click, since no physical transducer could reproduce that step instantaneously. Parameter smoothing keeps the audio thread stable during live automation.

---

## Limitations

* **Latency:** The high-order FIR filters required for clean interpolation and decimation inherently add group delay, preventing true zero-latency monitoring.
* **CPU Load:** The 8× oversampled non-linear core carries higher processing overhead than a single-rate implementation.
* **Filter Ringing:** Linear-phase filters preserve a time-aligned impulse response, but steep decimation filters can introduce minor pre-ringing on sharp transients.

---

## Takeaways

**Profiling**
I attached Visual Studio's ETW profiler to a live FL Studio session to measure real-world cost. The native-rate linear filters consumed minimal resources, and the high-order equiripple FIR filters stayed under 10% total CPU overhead. The isolated multi-rate design performed as intended without introducing numerical instability.

**Modular Architecture**
JUCE's `ProcessorChain` made for a clean, modular DSP architecture. Routing a multi-rate signal through isolated, well-defined stages proved significantly easier to reason about and debug than a monolithic processing block would have been.

Understanding the mathematics of aliasing allows for deliberate control over non-linear distortion, and demonstrates that this class of acoustic effect can be modeled effectively in the digital domain.
